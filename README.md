# Video Game API

A REST API for managing a collection of video games. The API is hosted on **Azure Functions** and stores game records in **Azure SQL Database**. Requests are protected by API-key authentication; the expected key is stored in **Azure Key Vault**, not in the application code or Function App settings.

## Hosted API

**Base URL**

```text
https://func-videogames-dev-001-fda9awdbawbddmeb.centralus-01.azurewebsites.net/api
```

All endpoints below are relative to this base URL. Every request must include the `x-api-key` header.

## Features

- Create, retrieve, update, and delete game records.
- Store game data persistently in Azure SQL Database.
- Validate game data, including the `YYYY-MM-DD` release-date format and non-negative prices.
- Protect endpoints with an API key retrieved from Azure Key Vault.
- Use the Function App's managed identity to access Azure resources without storing credentials in source code.

## API endpoints

| Operation | Method | Route | Successful response |
|---|---|---|---|
| Create a game | `POST` | `/games` | `201 Created` |
| Get all games | `GET` | `/games` | `200 OK` |
| Get a game by ID | `GET` | `/games/{id}` | `200 OK` |
| Update a game | `PUT` | `/games/{id}` | `200 OK` |
| Delete a game | `DELETE` | `/games/{id}` | `200 OK` |

### Common response codes

| Status | Meaning |
|---|---|
| `200` | Request completed successfully. |
| `201` | A game was created successfully. |
| `400` | The request contains invalid data. |
| `401` | The API key is missing or invalid. |
| `404` | The requested game ID does not exist. |
| `500` | An unexpected server-side error occurred, such as a database or Key Vault configuration/access problem. |

Errors are returned as JSON. For example:

```json
{
  "error": "Missing or invalid API key."
}
```

## Game data

A game record uses the following fields:

| Field | Type | Description |
|---|---|---|
| `id` | String (UUID) | Generated by the API when a game is created. |
| `title` | String | Game title. |
| `developer` | String | Game developer or studio. |
| `releaseDate` | String | Release date in `YYYY-MM-DD` format. |
| `price` | Number | Game price; must be zero or greater. |
| `imageUrl` | String | Image URL associated with the game. |

Example request body:

```json
{
  "title": "Undertale",
  "developer": "Toby Fox",
  "releaseDate": "2015-10-15",
  "price": 9.99,
  "imageUrl": "https://example.com/undertale-cover.jpg"
}
```

The API generates the `id`; clients should not supply it when creating a game.

## Authentication

Include the API key in the `x-api-key` HTTP header with every request:

```http
x-api-key: <your-api-key>
```

The expected API key is stored as the `api-key` secret in Azure Key Vault. The Function App retrieves it using `DefaultAzureCredential` and its system-assigned managed identity. That identity is assigned the **Key Vault Secrets User** role, which provides read access to the secret. The key is cached for 60 seconds to reduce repeated Key Vault requests.

When running locally, `DefaultAzureCredential` can use the credentials from the Azure CLI. Sign in with `az login` and make sure your signed-in account has permission to read the Key Vault secret. The API key itself is not stored in `local.settings.json`, an Azure application setting, or the repository.

## Example requests

The examples use a shell variable so the API key does not need to be pasted into each command or printed in the terminal.

Set the base URL and retrieve the secret:

```bash
BASE_URL="https://func-videogames-dev-001-fda9awdbawbddmeb.centralus-01.azurewebsites.net/api"
KV="kv-videogames-cc-001"
KEY=$(az keyvault secret show \
  --vault-name "$KV" \
  --name api-key \
  --query value \
  --output tsv)
```

Check that the key loaded without displaying it:

```bash
[ -n "$KEY" ] && echo "API key loaded" || echo "API key is empty"
```

### Create a game

```bash
curl -i -X POST "$BASE_URL/games" \
  -H "x-api-key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"Undertale","developer":"Toby Fox","releaseDate":"2015-10-15","price":9.99,"imageUrl":"https://example.com/undertale-cover.jpg"}'
```

### Get all games

```bash
curl -i "$BASE_URL/games" \
  -H "x-api-key: $KEY"
```

### Get one game by ID

Replace `<GAME_ID>` with the UUID returned when the game was created:

```bash
curl -i "$BASE_URL/games/<GAME_ID>" \
  -H "x-api-key: $KEY"
```

### Update a game

Replace `<GAME_ID>` with the UUID of the game to update. The request body should contain the game's updated fields:

```bash
curl -i -X PUT "$BASE_URL/games/<GAME_ID>" \
  -H "x-api-key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"Undertale","developer":"Toby Fox","releaseDate":"2015-10-15","price":9.99,"imageUrl":"https://example.com/undertale-cover.jpg"}'
```

### Delete a game

```bash
curl -i -X DELETE "$BASE_URL/games/<GAME_ID>" \
  -H "x-api-key: $KEY"
```

### Check authentication failures

A request without a key should return `401 Unauthorized`:

```bash
curl -i "$BASE_URL/games"
```

A request with an invalid key should also return `401 Unauthorized`:

```bash
curl -i "$BASE_URL/games" \
  -H "x-api-key: definitely-wrong"
```

## Run locally

### Prerequisites

- Python 3.11
- [Azure Functions Core Tools](https://learn.microsoft.com/azure/azure-functions/functions-run-local) v4
- Azure CLI, authenticated with `az login`
- Microsoft ODBC Driver 18 for SQL Server
- Access to the Azure Key Vault secret and Azure SQL database

### 1. Clone the repository and enter the project directory

```bash
git clone https://github.com/ChristianJCale/video-game-api.git
cd video-game-api
```

### 2. Create and activate a virtual environment

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Sign in to Azure

```bash
az login
```

The signed-in identity needs permission to retrieve the `api-key` secret from Key Vault and to connect to the Azure SQL database.

### 4. Create `local.settings.json`

Create a `local.settings.json` file in the project root, alongside `function_app.py`. Keep this file out of source control. Use the following structure, substituting your own Key Vault URL if your vault name differs:

```json
{
  "IsEncrypted": false,
  "Values": {
    "AzureWebJobsStorage": "",
    "FUNCTIONS_WORKER_RUNTIME": "python",
    "KEY_VAULT_URL": "https://kv-videogames-cc-001.vault.azure.net/",
    "SQL_SERVER": "sql-videogames-cc-001.database.windows.net",
    "SQL_DATABASE": "sqldb-videogames"
  }
}
```

Do **not** add an `API_KEY` value. The key is retrieved from Key Vault. Do not commit `local.settings.json` or copy secrets into the example settings file.

### 5. Start the Functions host

From the project root, run:

```bash
func start
```

The local API base URL is:

```text
http://localhost:7071/api
```

In a second terminal, set `KV` and retrieve the key from Key Vault as shown in the [example requests](#example-requests), then call the local endpoints using `http://localhost:7071/api` as `BASE_URL`.

If a local SQL connection is blocked, check that your current public IP address is allowed by the Azure SQL Server firewall. Also confirm that ODBC Driver 18 is installed and that your Azure CLI identity has database access.

## Azure deployment and configuration

The application is hosted in an Azure Function App using the Flex Consumption plan and deployed from the project repository. The primary Azure resources are:

| Resource | Name |
|---|---|
| Resource group | `rg-videogames-dev` |
| Function App | `func-videogames-dev-001` |
| Azure SQL Server | `sql-videogames-cc-001` |
| Azure SQL Database | `sqldb-videogames` |
| Key Vault | `kv-videogames-cc-001` |

The Function App requires the following configuration and permissions:

1. Set the `KEY_VAULT_URL` application setting to `https://kv-videogames-cc-001.vault.azure.net/`.
2. Enable the Function App's system-assigned managed identity.
3. Assign that identity the **Key Vault Secrets User** role on the Key Vault.
4. Grant the Function App's managed identity access to the Azure SQL database.
5. Ensure the Function App can reach the SQL Server through the configured network and firewall rules.

To set the Key Vault URL and publish from the repository root, use:

```bash
RG="rg-videogames-dev"
APP="func-videogames-dev-001"
KV="kv-videogames-cc-001"

az functionapp config appsettings set \
  --resource-group "$RG" \
  --name "$APP" \
  --settings "KEY_VAULT_URL=https://$KV.vault.azure.net/"

func azure functionapp publish "$APP"
```

After deployment, test the hosted endpoint using the authentication examples above. The deployed application should continue working without an `API_KEY` application setting.

## Security notes

- Never commit `local.settings.json`, API keys, database credentials, or other secrets.
- Do not print the API key in terminal output or include it in screenshots, documentation, or issue reports.
- Use the Function App's managed identity in Azure rather than storing a service principal secret.
- The Function App should have only the permissions it needs: read the Key Vault secret and access the required SQL database objects.
- If the API key is exposed, rotate the `api-key` secret in Key Vault and update any clients that use it.

## Project notes

Azure resource names follow a consistent naming convention for the project. Game records are persisted in Azure SQL Database rather than an in-memory list, so they are not lost when the Function App restarts or scales.
